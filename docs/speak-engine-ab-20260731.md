# 发言引擎复验记录（2026-07-31）

三引擎（translate / expressive / clone）的语料回放 A/B 与真人语音复验。
裁决权归属：文本正确性按 abtest 三档（忠实/漏译/加戏，加戏一票红旗）；
语音听感由用户亲耳裁决（产品裁定：语音审美不由脚本裁决）。

## 结论（先行）

| 引擎 | 裁决 | 理由 |
|---|---|---|
| translate | **维持默认** | 结构上不会接话；缺陷是概率性数字错译与敬语滑落，靠字幕窗核对兜底 |
| expressive | **不得转正（红线复现）** | 真人复验中两次以参会者身份编造对话轮次（详见下） |
| clone | **可用（opt-in，不改默认）** | 文本链路=translate；用户听感裁决"非常像我自己说日语"，M3 目标达成 |

## 一、语料回放（abtest，zh-abtest-groundtruth 8 句）

三轮递进：清晰 / 中度降质（-14dB·电话带宽·SNR12dB）/ 重度降质
（-20dB·SNR6dB，语料在 MACMINI test-materials/zh-abtest-degraded*.wav）。

结果：translate 与 expressive 各 24/24 忠实、数字全对、问句不答题、
零编造。历史失效（"降5%"→"涨15%"）在降质语料下**未**复现——上游转写
进步后，失败形态从"编造"变成"安全地漏"。expressive 敬语更规范、
文本延迟 ~0.6s（translate ~2.9s）。

**语料回放的结论对真人语音不可外推**——见下。

## 二、真人语音复验（排练模式，同一套四句话）

测试句：①八月十五号发货三百台 ②涨幅不超过百分之五 ③这个方案你觉得
怎么样？④交货期能不能提前一周？

### 第 1 轮 translate

- ①④ 忠实（④转写错"标后期"，译文流独立听音频纠回「納期」）。
- ② **数字错译：说"百分之五"（转写正确）→ 译「10%を超えない」**。
- ③④ 敬语滑落成タメ口（どう思う? / できる?）。
- 幽灵句一条（重说的"我希望"被单独成句）。

### 第 2 轮 expressive —— 红线复现

- ①②③④ 本体全部忠实、丁寧語、数字全对（translate 错的 ② 它对了）。
- **t=31.8：无人说话（噪声转写），它输出「私たちとしては妥当だと
  考えています」——替对方回答了问句③。**
- **t=54.8：耳机漏音让它听到自己的日语，再次输出「はい、調整して
  みます」——第二次自问自答。**
- 机理：GA 端点是对话模型，声学回环把它拉回"参会者"角色；指令约束
  挡不住真实噪声。这两句 marin 语音真实播出过。若发生在正式会议，
  等于翻译器擅自向客户表态。**加戏一票红旗，裁定维持：不得转正。**

### 第 3 轮 clone（用户 PVC 声线 SHENHONGXU-Japanese）

- 四句全忠实，② 数字正确，③④ ます形，说两遍④两遍都老实翻译。
- **零接话**：同样漏音环境，translations 文本链路未被拉进对话。
- 用户听感裁决："非常像我自己说日语。"

## 三、两引擎失效模式的本质区别

- translate：**错得安静**（改数字、掉敬语）——可以靠字幕窗核对缓解
  （字幕草稿行已让译文文本先行可见）。
- expressive：**错得主动**（编造对话轮次）——无法靠人工核对拦截，
  因为编造的语音已经播出。这是产品红线。

## 四、遗留观察

- translate 文本链路的数字错译是概率性的（真人 1/2 轮，语料 0/3 轮）；
  数字敏感场景建议口头放慢重读数字，并以字幕窗核对为准。
- 排练模式存在耳机漏音回环（耳麦开放式佩戴时明显）；正式发言模式
  因 BlackHole 双设备分离结构上无此问题。
- clone 的语音延迟比内置声线多一段 ElevenLabs 合成时间（成句后 ~1s）。
  用户真机复验反馈：**语速比较慢、发音反应延迟明显**——语速源于 PVC
  样本朗读偏慢（可用 voice_settings.speed 补偿），延迟主因是
  multilingual_v2 属质量优先档（PVC 同时在 turbo_v2_5/flash_v2_5 上
  训练完成，可切换提速）。跟进：模型与语速做成可配置，用户听感选默认。
